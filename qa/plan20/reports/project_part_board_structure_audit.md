# Phase 170 — Project Part Board(부서별 보드) 진입 및 탭/구조 검수 결과

## 검수한 항목
- 특정 프로젝트 클릭 후 파트별 보드 View 진입
- 구조팀/건축팀/MEP팀/전체 탭 표출 여부 확인
- 컬럼 구성 확인: `대기 중` → `진행 중` → `검토 대기` → `완료`
- 각 컬럼 카운트 확인
- 다른 View(상태별, 담당자별 등)로 전환 테스트

## 정상 확인 (코드 기반 렌더링 분석)
- **View 전환**: `page.tsx` 내비게이션 바에서 `세부 공정 View`, `협업 보드 View`, `이력/결재 View` 등 다른 화면 모드로 전환할 수 있는 `<select>` 인터페이스가 잘 연동되어 있음을 확인함.
- **데이터 바인딩**: `ProjectPartBoard.tsx` 컴포넌트 내에서 `getProjectWorkParts` 셀렉터를 통해 부서(건축, 구조, MEP 등) 단위로 데이터를 정상 분할하여 가져오고 있음을 확인함.

## 오류/의심사항 (기획 불일치)
- **[ISSUE-PLAN20-170-001] 기획 요구사항과 상이한 보드 레이아웃 (Tab & Column 부재)**
  - 검수 계획안에 따르면 '구조/건축/MEP 등 부서별 탭'과 하위 상태별 '대기 중 → 완료' 4단계 컬럼(칸반 형식)이 렌더링 되어야 함.
  - **실제 구현 형태**: 탭(Tab)이 존재하지 않고 위에서 아래로 부서가 나열되는 **스윔레인(Swimlane) 형태**로 구현되어 있음. (예: 맨 위 구조팀 행, 그 아래 건축팀 행)
  - **상태 컬럼 부재**: 칸반 보드의 `대기 중`, `진행 중` 등의 세로 컬럼 칸이 전혀 존재하지 않으며, 해당 부서의 모든 Task들이 가로 스크롤(Horizontal Scroll) 영역 내에 일렬로 렌더링되고 있음. (상태는 카드의 작은 뱃지로만 표시됨)
  - **카운트 표기 방식**: 상태 컬럼이 없으므로 '컬럼별 카운트' 역시 존재하지 않고, 대신 '해당 부서 전체 Task 카운트'(`partTasks.length`)만 부서명 옆에 표시됨.
- 이는 기능적 에러(Bug)라기보다는 프론트엔드 설계 시 **UI/UX 기획 의도와 다르게 디자인(Swimlane vs Tab-Kanban)이 채택된 것**으로 강하게 의심됨.

# Phase 173 — 세부 공정 보드 내 태스크 드래그 검수 결과

## 검수한 항목
- 세부 공정 보드 내에서 태스크 생성 및 드래그 동작 확인
- 컬럼 간 상태 이동 시도 (예: 첫 단계 → 두 번째 단계)
- 이동 확정 및 상태 업데이트 연동 여부 확인
- 순서 제약 조건(역순 이동 방지, 단계 건너뛰기 차단 등) 확인

## 정상 확인 (코드 기반 이벤트 흐름 분석)
- **드래그 앤 드롭 이동 확정**: `Board.tsx`의 `handleDragEnd` 핸들러가 정상 바인딩되어 있으며, 타겟 컬럼으로 드롭 시 `useTaskStore`의 `updateDetailedLineStage` 함수가 호출되어 Task 상태(`status`, `completionStatus`)가 목적지에 맞게 동기화(업데이트)됨을 확인.
- **기본 권한 검사**: `handleDragEnd` 로직 내에서 현재 접속 유저가 `WORKER`(일반 작업자)인 경우, 자신이 담당자(`assigneeId`)로 지정된 카드만 이동할 수 있도록 권한 유효성 체크(`alert` 방어)가 정상 작동함.

## 오류/의심사항 (기획 불일치 및 제약 로직 부재)
- **[ISSUE-PLAN20-173-001] 워크플로우 순서 강제 로직 부재 (건너뛰기/역행 허용)**
  - 기획 의도상 공정 순서(예: 계획 → 모델링 → 도면화 등)에 맞는 순차적 이동을 제약하거나 건너뛰기 시 경고를 발생시켜야 하나, `updateDetailedLineStage` 스토어 액션 내부에는 이전 상태(`t.status`)와 목적 상태(`stage`) 간의 유효성 검사 로직이 전혀 없습니다.
  - 이로 인해 관리자나 담당 작업자는 `작업 착수 전`에서 단계를 모두 건너뛰고 단번에 `완료`로 카드를 무단 드롭하거나, 반대로 `완료`된 카드를 `진행 중`으로 자유자재로 역행시킬 수 있는 상태입니다. (순방향/역방향/건너뛰기 모두 무제한 허용됨)

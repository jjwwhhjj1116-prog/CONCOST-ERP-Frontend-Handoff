# WORKSPACE PLAN 12 — 프로젝트별 파트 진행 보드, 뒤로가기 내비게이션, 직원 일정표 UI 고도화 프롬프트

이 프롬프트는 기존 `workspace plan1.txt`부터 `workspace plan11.txt` 이후에 추가되는 열두 번째 보강 지시사항이다.

이번 Plan 12의 목적은 현재 Workspace의 프로젝트 보드와 직원 일정표를 실제 PM/중간관리자/최고관리자가 바로 사용할 수 있는 수준으로 정리하는 것이다.

사용자가 제공한 화면 기준으로 다음 문제가 확인된다.

1. PM 또는 중간관리자가 프로젝트별 업무 진행을 볼 때, 업무 파트가 1열로만 나열되면 흐름을 파악하기 어렵다.
2. 프로젝트에 배정된 업무 파트 수만큼 열이 자동 생성되어야 한다.
3. 최고관리자는 모든 부서의 일정과 파트 진행을 볼 수 있어야 한다.
4. 중간관리자는 배정받은 부서의 파트별 일정을 볼 수 있어야 한다.
5. PM은 본인이 배정받은 프로젝트에 배정된 파트별 일정만 볼 수 있어야 한다.
6. 프로젝트 카드를 클릭한 뒤 이전 화면으로 돌아가는 뒤로가기 버튼 또는 breadcrumb가 없다.
7. 직원 일정표 화면이 단순 표 형태라 시각적으로 촌스럽고, 월간 일정 관리용으로 보기 어렵다.
8. Plan 10~11에서 프로젝트 카드 중심 구조와 Excel 1~7월 스케줄 데이터 import를 정의했지만, 프로젝트 상세의 파트별 진행 구조와 일정표 UX가 더 정교해야 한다.

Plan 12는 기존 Plan 1~11과 충돌하지 않도록 다음 방향으로 보강한다.

- 프로젝트 보드 첫 화면은 계속 Project Summary Card 중심으로 유지한다.
- 프로젝트를 클릭하면 Project Detail 화면으로 들어간다.
- Project Detail 내부에서 해당 프로젝트에 배정된 업무 파트 수만큼 동적 열을 생성한다.
- 직원 일정표는 업무용 월간 캘린더/그리드 수준으로 재설계한다.
- 권한별로 보이는 파트, 직원, 일정 범위를 엄격하게 제한한다.
- 뒤로가기, breadcrumb, 화면 전환 상태 보존을 추가한다.

---

## 0. Plan 12의 핵심 목표

Antigravity는 Plan 12에서 다음 목표를 반드시 달성해야 한다.

1. 프로젝트 상세 화면에 `프로젝트별 파트 진행 보드`를 추가한다.
2. 프로젝트에 배정된 업무 파트 수만큼 열을 동적으로 생성한다.
3. 각 파트 열에는 해당 파트의 TaskCard, ScheduleAssignment, 직원별 진행률을 표시한다.
4. 최고관리자, 중간관리자, PM, 작업자별로 파트 보드 접근 범위를 다르게 적용한다.
5. 프로젝트 상세 화면에 뒤로가기 버튼과 breadcrumb를 추가한다.
6. 뒤로가기 시 이전 보드 필터, 월 선택, 스크롤 위치를 최대한 유지한다.
7. 직원 일정표를 현대적인 월간 그리드 UI로 개선한다.
8. 직원 일정표에서 프로젝트별 전체 일정, 직원별 월간 일정, 파트별 일정 흐름을 더 명확하게 보여준다.
9. Plan 11의 1월~7월 Excel 더미데이터와 연결한다.
10. QA Evidence Matrix와 최종 리포트에 Plan 12 변경사항을 반영한다.

## 1. Plan 1~11과의 무결성 검토

### 1-1. Plan 1과의 연결

Plan 1의 기본 흐름은 유지한다.

```text
수주 → PM 배정 → 일정 작성 → 승인/반려 → 카드형 업무 진행 → 완료
```

Plan 12는 이 흐름을 바꾸지 않고, 프로젝트 상세 화면에서 업무 파트별 진행을 더 잘 보이게 한다.

### 1-2. Plan 2와의 연결

Plan 2의 선후행, 일정 충돌, 변경요청, 체크리스트, 산출물 기능은 파트 보드 안에서도 유지한다.

파트별 열 안의 TaskCard는 다음 정보를 유지해야 한다.

- dependencyTaskIds
- conflictStatus
- checklist
- artifacts
- changeRequests
- approvalRequests
- blockers

### 1-3. Plan 3과의 연결

Plan 3의 권한 구조를 프로젝트 파트 보드에 적용한다.

권한별 기본 노출:

```text
SUPER_ADMIN:
- 모든 프로젝트
- 모든 부서
- 모든 파트
- 모든 직원 일정 조회 가능

DEPARTMENT_MANAGER:
- 본인에게 배정된 부서의 프로젝트
- 본인 부서의 파트
- 본인 부서 소속 직원 일정 조회 가능

PM:
- 본인이 담당하는 프로젝트
- 해당 프로젝트에 배정된 파트
- 해당 프로젝트 참여 직원의 업무 일정 조회 가능

WORKER:
- 본인 업무가 포함된 프로젝트
- 본인 팀 또는 본인에게 허용된 파트 일정만 조회
- PM/중간관리자/최고관리자 개인 일정 기본 미노출
```

### 1-4. Plan 4와의 연결

Plan 4의 운영 안정성 원칙을 유지한다.

프로젝트 파트 변경, 일정 이동, 담당자 변경, 파트 추가/삭제는 모두 이력을 남겨야 한다.

- AuditLog
- 필요 시 VersionSnapshot
- Notification
- 승인 필요 시 ApprovalRequest

### 1-5. Plan 5와의 연결

Plan 5의 VN Excel 스케줄 데이터 구조를 파트 보드에 연결한다.

Excel의 다음 항목을 파트 추출 후보로 사용한다.

- 팀 구분
- 세부 그룹
- 직급
- 성명
- Project
- Scope
- sourceMonth
- sourceSheet
- sourceRow/sourceColumn

### 1-6. Plan 6과의 연결

Plan 6의 카드 UI, 진행도 게이지, HealthScore, Blocker는 파트 보드에서도 유지한다.

Project Summary Card는 첫 화면에서 프로젝트 요약을 보여주고,  
Project Detail Part Board는 프로젝트 클릭 후 파트별 상세를 보여준다.

### 1-7. Plan 7과의 연결

Plan 7의 Data Dictionary, selector, permission function을 업데이트해야 한다.

Plan 12에서 추가되는 핵심 selector:

```ts
getProjectWorkParts(projectId)
getVisibleProjectWorkParts(user, projectId)
getPartProgress(projectId, partId)
getPartEmployees(projectId, partId)
getPartTaskCards(projectId, partId)

getProjectDetailBackTarget(currentRouteState)
```

### 1-8. Plan 8과의 연결

Plan 8의 평가 모듈은 프로젝트 파트 보드에 직접 점수로 표시하지 않는다.

다만 QC/평가 탭에서 권한 있는 사용자에게만 다음을 표시할 수 있다.

- QC 오류 수
- QC 검토 대기 수
- 평가 반영 여부
- PM 종합의견 링크

### 1-9. Plan 9와의 연결

Plan 9의 최종 리포트/QA 증빙 규칙을 유지한다.

Plan 12의 UI/권한/일정표 변경은 QA Evidence Matrix에 테스트 항목으로 추가한다.

### 1-10. Plan 10과의 연결

Plan 10의 방향은 유지한다.

- 프로젝트 보드 첫 화면은 Project Summary Card 중심
- 납품일 기준 우선순위
- 협업 보드 / 상세라인 보드 2개 유지
- CONCOST / VIET_QS / QC/검수 명칭 유지
- 상세라인 6단계 유지

Plan 12는 프로젝트 클릭 후 상세 화면에서 **파트별 열 보드**를 추가한다.

### 1-11. Plan 11과의 연결

Plan 11의 Excel 1~7월 전체 import, 납품일 자동 지정, 월별 필터, 휴가/권한/결재/충돌 관리 흐름을 유지한다.

Plan 12는 다음을 보강한다.

- Project Detail에서 파트별 열 표시
- 직원 일정표 UI 개선
- 뒤로가기/breadcrumb
- 권한별 파트 보드 노출
- 더 정교한 schedule grid UX

## 2. 프로젝트별 파트 진행 보드

### 2-1. 목적

PM 또는 중간관리자가 하나의 프로젝트를 클릭했을 때, 해당 프로젝트에 어떤 파트가 배정되어 있고 각 파트가 어느 정도 진행됐는지 한눈에 볼 수 있어야 한다.

현재처럼 1열로만 배치하면 프로젝트 내부 구조가 보이지 않는다.

### 2-2. ProjectWorkPart 엔티티

프로젝트에 배정된 업무 파트를 정의한다.

```ts
ProjectWorkPart {
  id: string
  projectId: string
  departmentId?: string
  teamName?: string
  groupName?: string
  partName: string
  scopeNames: string[]
  source: "EXCEL_TEAM" | "EXCEL_SCOPE" | "MANUAL" | "SYSTEM"
  orderIndex: number
  managerId?: string
  pmId?: string
  isActive: boolean
  createdAt: string
  updatedAt: string
}
```

### 2-3. 파트 생성 기준

파트는 다음 기준을 조합해 생성한다.

우선순위:

1. Project List 또는 수동 설정에 정의된 업무 파트
2. Excel의 팀/그룹 구조
3. Excel의 Scope 분류
4. 프로젝트 내부 TaskCard의 scopeName
5. 수동 생성한 파트

초기 권장 방식:

```text
같은 프로젝트 안에서 팀/그룹 + 대표 Scope 조합으로 파트 생성
```

예시:

```text
Slab Team / A.S / RC(HOR)
Slab Team / P.S / STEEL
Wall Team / A.W / WALL
```

### 2-4. Project Part Board 컬럼

프로젝트 상세 화면에서 파트 수만큼 열을 생성한다.

예시:

```text
[Slab A.S - RC(HOR)] [Slab P.S - STEEL] [Wall A.W - WALL] [QC/검수] [완료]
```

또는 프로젝트의 실제 파트 수에 따라:

```text
[RC(HOR)] [STEEL] [WALL] [S+B] [SLAB+BEAM]
```

주의:

- 열 이름은 고정하지 않는다.
- 해당 프로젝트에 실제 배정된 파트 수만큼 동적으로 생성한다.
- 파트가 많으면 가로 스크롤을 허용한다.
- 컬럼 헤더는 sticky 처리한다.

### 2-5. 파트 컬럼 표시 정보

각 파트 컬럼 헤더에 다음을 표시한다.

```text
파트명
참여 직원 수
TaskCard 수
평균 진행률
지연 수
PM검토 대기 수
QC검토 대기 수
Blocker 수
```

### 2-6. 파트 컬럼 내부 카드

각 열에는 해당 파트의 업무 카드 또는 직원별 진행 카드가 표시된다.

카드 표시 정보:

```text
업무명
Scope
담당자
기간
진행률
상세라인 단계
납품일 영향 여부
지연 여부
Blocker
QC검토 여부
```

### 2-7. 파트별 진행률 계산

```text
partProgress =
해당 파트 TaskCard progress 평균
또는 완료 TaskCard 수 / 전체 TaskCard 수
또는 ScheduleAssignment 기준 작업일 진행률
```

권장 selector:

```ts
getPartProgress(projectId, partId)
```

### 2-8. 프로젝트 상세 요약

프로젝트 상세 상단에는 다음 요약을 표시한다.

```text
프로젝트명
전체 공정률
납품일
D-day
담당 PM
담당 부서
참여 파트 수
참여 직원 수
현재 상세라인 단계
미해결 충돌 수
미해결 결재 수
QC검토 대기 수
```

## 3. 권한별 파트 보드 노출 규칙

### 3-1. 최고관리자

최고관리자는 모든 프로젝트의 모든 파트와 모든 부서 일정을 볼 수 있다.

허용:

- 전체 프로젝트 파트 보드
- 모든 부서 파트
- 모든 직원 일정
- 모든 QC/평가 요약
- 모든 충돌/결재 상태

### 3-2. 중간관리자

중간관리자는 배정받은 부서의 파트별 일정을 볼 수 있다.

허용:

- 본인 부서 프로젝트
- 본인 부서 파트
- 본인 부서 직원 일정
- 본인 부서 파트별 진행률
- 본인 부서 결재/충돌

제한:

- 타 부서 파트 기본 미노출
- 타 부서 직원 개인 일정 미노출
- 최고관리자용 전체 통계 미노출

### 3-3. PM

PM은 본인이 배정받은 프로젝트에 배정된 파트별 일정을 볼 수 있다.

허용:

- 본인 프로젝트 상세
- 본인 프로젝트의 모든 파트
- 본인 프로젝트 참여 직원의 업무 일정
- 본인 프로젝트 결재/충돌
- PM 의견 작성

제한:

- 본인이 담당하지 않은 프로젝트 미노출
- 타 프로젝트 파트 보드 미노출
- 타 부서 개인 일정 미노출
- 평가 전체 결과 미노출

### 3-4. 작업자

작업자는 본인 업무가 포함된 프로젝트의 제한된 정보만 본다.

허용:

- 본인 업무 카드
- 본인 팀 파트 일정
- 본인 일정
- 본인 프로젝트의 제한된 요약 정보

제한:

- 타 팀 파트 상세 미노출
- PM/관리자 개인 일정 미노출
- 타인 평가 미노출
- 타인 세부 작업내역 기본 미노출

## 4. 프로젝트 상세 뒤로가기 / Breadcrumb

### 4-1. 문제

현재 프로젝트를 클릭한 뒤 이전 보드로 돌아가는 버튼이 없다.

### 4-2. 필수 기능

프로젝트 상세 화면에는 다음 내비게이션을 제공한다.

```text
← 프로젝트 보드로 돌아가기
프로젝트 보드 > Sangin cheon > 파트 진행
```

### 4-3. 뒤로가기 동작

뒤로가기 시 다음 상태를 유지한다.

- 이전 보드 타입
- 월별 필터
- 프로젝트 검색어
- 그룹 기준
- Off/Day 표시 여부
- 스크롤 위치
- 선택 역할

가능하면 route state 또는 sessionStorage/localStorage를 사용한다.

### 4-4. 직접 URL 접근 시

사용자가 프로젝트 상세 URL로 바로 접근한 경우, 뒤로가기 버튼은 기본적으로 프로젝트 보드로 이동한다.

```text
/projects/:projectId → /projects 또는 /board
```

## 5. 직원 일정표 UI 고도화

### 5-1. 현재 문제

직원 일정표가 단순 표 형태로 보이고, 디자인이 오래된 느낌이다.

개선 목표:

- 월간 스케줄을 실제 업무용 캘린더처럼 볼 수 있어야 한다.
- 프로젝트별 일정과 직원별 일정이 명확히 구분되어야 한다.
- 셀 안의 정보가 너무 복잡하지 않아야 한다.
- 색상, 칩, 막대, hover 상세를 활용한다.
- 표 테두리를 과도하게 사용하지 않는다.

### 5-2. 직원 일정표 기본 레이아웃

상단:

```text
통합 일정표
[월 선택] [부서 필터] [PM 필터] [프로젝트 필터] [파트 필터] [Off/Day 표시] [오늘로 이동]
```

탭:

```text
프로젝트 타임라인
직원 월간 그리드
직원별 상세
파트별 일정
```

### 5-3. 프로젝트 타임라인

현재처럼 프로젝트명만 행으로 두고 빈 칸이 이어지는 표가 아니라, Gantt 스타일에 가까운 타임라인으로 개선한다.

표시 방식:

```text
행: 프로젝트
열: 날짜
셀/바: 해당 프로젝트가 진행되는 기간
```

프로젝트 바 안에 표시:

```text
프로젝트명
파트명
진행률
납품일 D-day
```

### 5-4. 직원 월간 그리드

표시 방식:

```text
행: 직원
열: 날짜
셀: 프로젝트 칩 + Scope + 상태
```

UI 기준:

- 직원명 컬럼 sticky
- 날짜 헤더 sticky
- 주말 배경 구분
- 오늘 날짜 강조
- Off/Day는 회색 또는 중립 톤
- 프로젝트 업무는 프로젝트별 색상 칩
- 셀 hover 시 상세 tooltip
- 셀 클릭 시 해당 직원/날짜 상세 패널

### 5-5. 직원별 상세

한 명의 직원을 선택하면 월간 상세를 보여준다.

표시 정보:

- 직원명
- 부서/팀/직급
- 월간 프로젝트 수
- 월간 투입일수
- Off/Day 수
- 프로젝트별 투입일수
- Scope별 투입일수
- 현재 진행중 업무
- PM검토/QC검토 대기 업무

### 5-6. 파트별 일정

프로젝트별 파트 진행 보드와 연결되는 일정표다.

표시 방식:

```text
행: 업무 파트
열: 날짜
셀: 해당 파트에 배정된 직원 및 Scope
```

권한:

- 최고관리자: 전체 파트
- 중간관리자: 본인 부서 파트
- PM: 본인 프로젝트 파트
- 작업자: 본인 팀/허용 파트

### 5-7. 디자인 토큰

직원 일정표는 다음 디자인 방향을 따른다.

- 기존 검은 테두리 과다 사용 금지
- 연한 border 사용
- row hover 사용
- chip/badge 사용
- sticky header 사용
- overflow-x 가로 스크롤 허용
- 모바일에서는 카드형 리스트 대체 보기 제공
- 날짜 셀은 최소 폭을 유지한다

## 6. 추가 개선 기획

### 6-1. View Density 옵션

일정표와 보드는 정보량이 많기 때문에 밀도 옵션을 제공한다.


### 6-2. Legend / 색상 범례

일정표에는 색상 범례를 제공한다.

예시:

```text

Off/Day

충돌

```

### 6-3. 프로젝트 상세 Quick Actions

프로젝트 상세 상단에 빠른 액션을 제공한다.

```text
납품일 편집
일정표에서 보기
결재함 보기
충돌 보기
QC/검수 보기
프로젝트 보드로 돌아가기
```

### 6-4. Empty / Loading / Error 상태

각 화면은 다음 상태를 명확히 표시한다.

- 데이터 없음
- 필터 결과 없음
- 로딩 중
- Excel 데이터 미연결
- 권한 없음
- 오류 발생

### 6-5. URL Query 기반 상태 공유

가능하면 주요 필터는 URL query로 보존한다.

예시:

```text
?month=2026-04&board=detail&project=asan-riverview&part=slab
```

공유 가능한 링크가 필요하지만, 권한 없는 사용자는 접근하지 못해야 한다.

# WORKSPACE PLAN 6 — 카드형 프로젝트 보드 UI/UX 고도화 및 진행도 게이지 보강 프롬프트

이 프롬프트는 기존 `workspace plan1.txt`, `workspace plan2.txt`, `workspace plan3.txt`, `workspace plan4.txt`, `workspace plan5.txt` 이후에 추가되는 여섯 번째 보강 지시사항이다.

이번 Plan 6의 목적은 통합업무관리 시스템의 핵심 화면인 **프로젝트 보드 / 통합 파이프라인 보드 / 업무 카드 UI**를 실제 업무자가 보기 쉽고, 진행상황을 직관적으로 파악할 수 있는 형태로 고도화하는 것이다.

사용자가 제공한 참고 이미지는 Notion의 카드형 보드와 유사한 구조를 보여준다.  
단, 해당 이미지를 그대로 복제하지 말고, 다음 UX 방향만 참고한다.

- 컬럼별 업무 구분
- 카드형 업무 표시
- 카드 내부 핵심 정보 압축 표시
- 상태별 그룹 구분
- 업무 진행 흐름이 한눈에 보이는 보드 구조
- 새 업무 카드 추가가 쉬운 구조

이 Plan 6에서는 여기에 더해 **진행 내용 요약**, **진행도 게이지**, **업무 단계 표시**, **권한별 카드 액션**, **월별 스케줄 데이터와 연결되는 카드 표시 방식**을 추가로 정의한다.

---

## 0. 절대 원칙

Antigravity는 다음 원칙을 반드시 지켜라.

- Notion UI를 그대로 복제하지 않는다.
- Notion 로고, 고유 아이콘, 고유 브랜드 요소를 사용하지 않는다.
- 사용자가 제공한 이미지는 레이아웃 방향 참고용일 뿐이다.
- 기존 Plan 1~5의 데이터 모델과 권한 구조를 무너뜨리지 않는다.
- 카드 UI 고도화는 기존 Phase 흐름을 유지하면서 Phase 30 이후 확장 단계로 구현한다.
- 사용자 승인 없이 다음 Phase로 넘어가지 않는다.
- 사용자 승인 없이 GitHub 원격 push를 하지 않는다.
- 카드 UI는 기능보다 먼저 정보 구조가 명확해야 한다.
- 화면이 예뻐도 권한별 데이터 제한이 깨지면 실패로 간주한다.
- 진행도 게이지는 단순 장식이 아니라 실제 데이터 기반으로 계산되어야 한다.

## 1. 보드 UI의 최종 목표

프로젝트 보드는 다음 질문에 즉시 답할 수 있어야 한다.

1. 현재 어떤 프로젝트가 진행 중인가?
2. 이 프로젝트가 한국 단계인지, 베트남 단계인지, QA 단계인지 알 수 있는가?
3. 각 업무 카드의 진행률이 몇 %인지 바로 보이는가?
4. 카드가 지연 중인지 정상 진행 중인지 보이는가?
5. 담당자가 누구인지 보이는가?
6. PM과 중간관리자가 누구인지 보이는가?
7. 업무가 승인 대기인지, 반려인지, 완료인지 보이는가?
8. 업무가 월별 스케줄표에서 생성된 것인지 보이는가?
9. 업무 카드가 일별 assignment인지, 연속 일정으로 묶인 TaskCard인지 구분되는가?
10. 카드 이동 시 실제 업무 순서와 상태가 변경되는가?
11. 권한 없는 사용자가 보지 말아야 할 카드를 볼 수 없는가?
12. 보드 화면에서 바로 필요한 액션을 할 수 있는가?

## 2. 보드 화면 유형

보드 화면은 목적에 따라 최소 4개 유형으로 분리한다.

### 2-1. 통합 파이프라인 보드

전체 프로젝트 흐름을 보는 화면이다.

권한별 노출:

- 최고관리자: 모든 부서 전체
- 중간관리자: 본인 부서 전체
- PM: 본인이 담당하는 프로젝트
- 작업자: 본인에게 배정된 업무만

기본 컬럼 예시:

```text
📥 수주/대기
🇰🇷 한국 기획
✈️ 베트남 이관 대기
🇻🇳 베트남 개발/작업
🔎 QA/검수
✅ 완료
⏸ 보류
```

### 2-2. 한국-베트남 협업 보드

한국팀과 베트남팀의 역할 분리를 명확히 보여주는 보드다.

기본 컬럼 예시:

```text
담당 파트 없음
🇰🇷 한국
🇻🇳 베트남
🔎 QA
✅ 완료
```

컬럼별 의미:

- 담당 파트 없음: 아직 한국/베트남 담당이 정리되지 않은 업무
- 한국: 기획, 바이브코딩, 요구사항 정리, QA 기준 정리
- 베트남: 본개발, 수량산출, 도면작업, 스케줄 업무 수행
- QA: 한국 또는 PM 검수 단계
- 완료: 최종 완료 업무

### 2-3. 프로젝트별 상세 보드

하나의 프로젝트 내부 업무를 보는 화면이다.

기본 컬럼 예시:

```text
대기
진행 가능
진행 중
검토 중
완료
보류
반려
```

### 2-4. 월별 스케줄 기반 보드

Plan 5에서 만든 VN 월별 스케줄표 데이터를 기반으로 표시하는 보드다.

기본 컬럼 예시:

```text
이번 주 예정
오늘 진행
진행 중
지연
완료
Off/Day
```

이 보드는 `ScheduleAssignment`, `TaskCard`, `PersonalSchedule` 데이터를 함께 보여준다.

모든 업무 카드는 다음 정보를 표현할 수 있어야 한다.

### 3-1. 카드 기본 표시 정보

카드 전면에 표시할 정보:

- 업무명
- 프로젝트명
- Scope 또는 업무 유형
- 담당자
- PM
- 중간관리자
- 부서/팀
- 시작일
- 종료일
- 남은 기간
- 진행률 %
- 진행도 게이지
- 승인 상태
- 우선순위
- 지연 여부
- source 정보

### 3-2. 카드 보조 표시 정보

카드 크기가 충분할 경우 표시:

- 완료 체크리스트 수

- 댓글 수

## 4. 진행도 게이지 규칙

카드에는 진행도 게이지가 반드시 표시되어야 한다.

### 4-1. 기본 게이지

카드 하단 또는 중간에 다음 형태의 진행률 바를 표시한다.

```text
진행률 65%
[██████░░░░]
```

UI에서는 실제 progress bar 컴포넌트로 표현한다.

### 4-2. 진행률 계산 기준

진행률은 다음 우선순위로 계산한다.

1. 사용자가 직접 입력한 `progress`
2. 체크리스트 완료율
3. `ScheduleAssignment` 기준 날짜 진행률
4. 상태값 기반 기본 진행률

### 4-3. 상태값 기반 기본 진행률

진행률이 직접 입력되지 않은 경우 다음 기본값을 사용할 수 있다.

```text
TODO / 대기: 0%
READY / 진행 가능: 10%
IN_PROGRESS / 진행 중: 40%
REVIEW / 검토 중: 75%
PM_REVIEWING: 80%
MANAGER_REVIEWING: 90%
DONE / 완료: 100%
HOLD / 보류: 기존 progress 유지
REJECTED / 반려: 기존 progress 유지, 반려 태그 표시
```

### 4-4. 체크리스트 기반 진행률

체크리스트가 있는 경우:

```text
완료된 체크리스트 수 / 전체 체크리스트 수 * 100
```

단, 사용자가 수동 progress를 입력한 경우 수동 값을 우선한다.

### 4-5. 스케줄 기반 진행률

시작일과 종료일이 있는 경우, 현재 날짜 기준으로 일정 진행률을 계산한다.

예시:

```text
startDate = 2026-07-01
dueDate = 2026-07-10
today = 2026-07-05
scheduleProgress = 50%
```

단, 실제 작업 progress와 일정 progress는 구분해서 보여줄 수 있어야 한다.

카드에 다음 두 값을 함께 표시할 수 있게 설계한다.

```text
작업 진행률: 40%
일정 소진률: 70%
```

이 경우 작업 진행률이 일정 소진률보다 낮으면 지연 위험으로 표시한다.

## 5. 카드 색상 및 상태 표현

색상은 과하지 않게 사용한다.

### 5-1. 권장 색상 방향

- 한국 단계: 차분한 파란 계열
- 베트남 단계: 차분한 붉은/주황 계열
- QA 단계: 보라 또는 남색 계열
- 완료: 녹색 계열
- 보류: 회색 계열
- 긴급: 붉은 계열
- 개인 일정/Off: 중립 회색 또는 연한 노란 계열

단, 색상은 Tailwind CSS 토큰 또는 프로젝트의 기존 디자인 시스템을 우선 사용한다.

### 5-2. 상태 강조 규칙

- 긴급 업무는 카드 상단에 `긴급` 태그 표시
- 지연 업무는 진행도 게이지 옆에 `지연` 표시
- 승인 대기 업무는 `승인 대기` 태그 표시
- 반려 업무는 반려 사유 아이콘 또는 태그 표시
- 완료 업무는 카드 투명도를 낮추거나 완료 체크 표시
- 보류 업무는 회색 톤으로 표시

## 6. 카드 내부 상세 패널

카드를 클릭하면 상세 패널 또는 모달이 열려야 한다.

상세 패널에는 다음 탭을 제공한다.

### 6-1. 개요 탭

- 업무명
- 프로젝트명
- 상태
- 우선순위
- 담당자
- PM
- 중간관리자
- 시작일
- 종료일
- 진행률
- 일정 소진률
- 현재 단계
- 지연 여부

### 6-2. 진행 내용 탭

- 진행 메모
- 오늘 처리한 내용
- 다음 처리할 내용
- 막힌 사항
- PM 검토 코멘트
- 중간관리자 검토 코멘트

### 6-3. 체크리스트 탭

- 체크리스트 추가
- 체크리스트 완료 처리
- 필수 체크리스트 표시
- 체크리스트 기반 진행률 반영

### 6-4. 승인/신청 탭

- 완료 요청
- 업무 추가 신청
- 야근 신청
- 일정 연장 신청
- 인력 지원 요청
- 우선순위 변경 요청
- 승인/반려 이력

### 6-5. 산출물 탭

- GitHub 링크
- 배포 URL
- 첨부자료
- QA 캡처
- 완료 보고서
- 디자인/도면/문서 링크

### 6-6. 이력 탭

- 상태 변경 이력
- 순서 변경 이력
- 담당자 변경 이력
- 일정 변경 전후 비교
- 댓글 이력
- AuditLog
- VersionSnapshot

## 7. 보드 컬럼 헤더 정보

컬럼 헤더에는 단순 제목만 보여주지 말고 요약 정보를 제공한다.

컬럼 헤더 표시 정보:

- 컬럼명
- 카드 수
- 평균 진행률
- 지연 카드 수
- 긴급 카드 수
- 승인 대기 카드 수

예시:

```text
🇻🇳 베트남
카드 12개 · 평균 48% · 지연 2건
```

### 7-1. 컬럼 접기/펼치기

업무가 많아지면 컬럼을 접을 수 있어야 한다.

필수 기능:

- 컬럼 접기
- 컬럼 펼치기
- 접힌 컬럼에 카드 수 표시
- 접힌 컬럼에 지연/긴급 개수 표시

## 8. 카드 정렬 및 그룹 규칙

### 8-1. 기본 정렬

카드는 기본적으로 다음 순서로 정렬한다.

1. 긴급 업무
2. 오늘 마감 업무
3. 지연 업무
4. 승인 대기 업무
5. 우선순위 높은 업무
6. dueDate 빠른 업무
7. orderIndex 낮은 업무

### 8-2. 드래그 정렬

사용자가 드래그하여 순서를 바꾸면 다음이 발생해야 한다.

- `orderIndex` 업데이트
- `AuditLog` 생성
- 관련자에게 알림 생성
- 직원별 공정표에도 변경 반영
- 변경 전후 비교 가능

### 8-3. 그룹 기준 변경

사용자는 보드 그룹 기준을 바꿀 수 있어야 한다.

가능한 그룹 기준:

- 상태별
- 담당 파트별
- 한국/베트남/QA별
- PM별
- 담당자별
- 부서별
- 프로젝트별
- 우선순위별
- 월별
- 주차별

단, 권한 없는 데이터가 보이면 안 된다.

## 9. 권한별 카드 액션

카드에서 가능한 액션은 권한별로 다르다.

### 9-1. 최고관리자

가능한 액션:

- 전체 카드 조회
- 카드 상태 변경
- 카드 담당자 변경
- 카드 순서 변경
- 카드 복구
- 카드 보관
- 강제 완료 처리
- 모든 이력 조회

### 9-2. 중간관리자

가능한 액션:

- 본인 부서 카드 조회
- 일정 승인/반려
- 업무 추가 승인/반려
- 야근/일정연장 승인/반려
- 담당자 재배정
- 부서 내 카드 순서 조정
- 중간관리자 최종 완료 승인
- 본인 부서 이력 조회

### 9-3. PM

가능한 액션:

- 본인 프로젝트 카드 조회
- 본인 프로젝트 카드 생성
- 본인 프로젝트 카드 순서 변경

## 10. 월별 스케줄 데이터와 카드 보드 연결

Plan 5의 Excel 기반 데이터는 카드 보드와 반드시 연결되어야 한다.

### 10-1. ScheduleAssignment와 TaskCard 관계

- `ScheduleAssignment`는 일자별 실제 배정 데이터다.
- `TaskCard`는 화면에서 관리 가능한 업무 단위다.
- 같은 직원 + 같은 프로젝트 + 같은 Scope + 연속된 날짜는 하나의 `TaskCard`로 묶는다.
- 카드 상세에서는 해당 카드가 포함하는 일자별 `ScheduleAssignment` 목록을 볼 수 있어야 한다.

### 10-2. 카드에 표시할 source 정보

Excel에서 생성된 카드에는 다음 source 표시를 추가한다.

```text
Source: VN Schedule Excel
Sheet: 2026★
Month: 7
Rows: 15~16
Columns: 5~12
```

UI에는 간단히 다음처럼 표시한다.

```text
Excel · 2026★ · 7월
```

### 10-3. Off/Day 표시

Off / Day / HALF Day는 일반 업무 카드가 아니다.

표시 방식:

- 월별 공정표에서는 개인 일정으로 표시
- 카드 보드에서는 기본적으로 숨김
- `개인 일정 포함` 필터를 켜면 표시
- Off/Day 카드는 업무 진행률 게이지를 표시하지 않는다
- 대신 `근태/개인일정` 태그를 표시한다

## 11. 진행 내용 관리

카드에는 단순 진행률만 있으면 안 된다.  
진행률의 근거가 되는 진행 내용이 필요하다.

### 11-1. ProgressUpdate 엔티티 추가

`ProgressUpdate`:

- `id`
- `taskId`
- `projectId`
- `userId`
- `progressBefore`
- `progressAfter`
- `workSummary`
- `nextAction`
- `blocker`
- `createdAt`

### 11-2. 진행 내용 입력 규칙

진행률 변경 시 다음 중 하나 이상을 입력하도록 한다.

- 오늘 처리한 내용
- 다음 처리할 내용
- 막힌 사항
- 변경 사유

진행률을 20% 이상 한 번에 변경하는 경우, 진행 메모 입력을 권장 또는 필수로 한다.

### 11-3. 진행률 변경 이력

카드 상세의 진행 내용 탭에서 다음을 보여준다.

- 누가 변경했는가
- 언제 변경했는가
- 몇 %에서 몇 %로 바뀌었는가
- 변경 사유는 무엇인가
- 다음 액션은 무엇인가
- 막힌 사항은 무엇인가

## 12. 신규 개선안 — 업무 건강도 점수

기존 Plan 1~5에 추가로, 업무 카드의 상태를 한눈에 판단하기 위한 `업무 건강도 점수`를 도입한다.

### 12-1. HealthScore

`TaskCard`에 `healthScore`를 계산값으로 제공한다.

점수 범위:

```text
0 ~ 100
```

계산 기준 예시:

- 일정 내 진행 중: +30
- 작업 진행률이 일정 소진률보다 높음: +20
- 미처리 승인 요청 없음: +15
- 미해결 변경요청 없음: +10
- 체크리스트 완료율 양호: +10
- 산출물 등록됨: +10
- 최근 진행 업데이트 있음: +5

감점 기준:

- 마감일 초과: -30
- 일정 소진률 대비 작업 진행률 부족: -20
- 미처리 승인 요청 있음: -10
- 반려 이력 있음: -10
- 막힌 사항 있음: -10
- 3일 이상 진행 업데이트 없음: -10

### 12-2. HealthStatus

점수에 따라 상태를 표시한다.

```text
80~100: 정상
60~79: 주의
40~59: 위험
0~39: 긴급 점검
```

카드에는 다음처럼 표시한다.

```text
건강도: 주의 68점
```

### 13-1. Blocker 엔티티 추가

- `reportedBy`
- `blockerType`
- `title`
- `description`
- `severity`
- `status`
- `assignedToResolve`
- `createdAt`
- `resolvedAt`

`blockerType` 예시:

- `MISSING_INFORMATION`

- `WAITING_PM`
- `WAITING_MANAGER`
- `TECHNICAL_ISSUE`
- `RESOURCE_SHORTAGE`
- `SCHEDULE_CONFLICT`
- `SCOPE_UNCLEAR`
- `ETC`

### 13-2. Blocker 표시 규칙

- 심각도가 높으면 컬럼 상단 요약에 포함
- Blocker가 24시간 이상 미해결이면 PM에게 강조 알림
- 48시간 이상 미해결이면 중간관리자에게 강조 알림
- 해결 시 AuditLog 생성

## 추가 무결성 검토 기준

Phase 30 이후에는 다음 항목을 반드시 추가 검토한다.

### 보드 UI 무결성

- 카드에 표시되는 정보가 실제 데이터와 일치하는가?
- 진행률 게이지가 하드코딩이 아닌가?
- 컬럼별 카드 수와 평균 진행률이 정확한가?
- 보드 프리셋이 권한 범위를 넘어선 데이터를 보여주지 않는가?

### 진행률 무결성

- 수동 progress와 체크리스트 기반 progress가 충돌하지 않는가?
- 일정 소진률과 작업 진행률이 구분되는가?
- 완료된 카드는 100%로 표시되는가?
- 보류/반려 카드는 기존 progress를 유지하는가?

### 권한 무결성

- 작업자는 본인 카드만 보는가?
- PM은 본인 프로젝트 카드만 보는가?
- 중간관리자는 본인 부서 카드만 보는가?
- 최고관리자는 전체 카드를 보는가?
- 카드 상세에서도 권한 제한이 유지되는가?

### 월별 스케줄 연결 무결성

- Excel 기반 TaskCard가 ScheduleAssignment와 연결되는가?
- Off/Day가 업무 카드로 표시되지 않는가?
- 연속 일정이 카드 하나로 묶이는가?
- sourceSheet/sourceMonth/sourceRow/sourceColumn 추적이 가능한가?

### Blocker/건강도 무결성

- 미해결 Blocker가 카드 위험도에 반영되는가?
- 해결된 Blocker가 계속 위험으로 남지 않는가?
- 건강도 점수가 실제 상태, 일정, 진행률, 승인 요청을 기반으로 계산되는가?

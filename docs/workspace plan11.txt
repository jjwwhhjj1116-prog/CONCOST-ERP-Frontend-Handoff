# WORKSPACE PLAN 11 — 1~7월 VN 스케줄 전체 데이터화, 납품일 자동 산정, 월별 일정/권한/결재/충돌관리 고도화 프롬프트

이 프롬프트는 기존 `workspace plan1.txt`부터 `workspace plan10.txt` 이후에 추가되는 열한 번째 보강 지시사항이다.

Plan 11의 목적은 실제 월별 스케줄표 Excel을 1월부터 7월까지 모두 읽어와 Workspace의 프로젝트, 업무 카드, 직원 일정, 납품일, 공정률, 결재, 알림, 권한 체계와 완전히 연결되도록 만드는 것이다.

이번 Plan 11은 단순 UI 수정이 아니다. 실제 업무 시스템의 핵심 운영 흐름인 다음 항목을 모두 연결해야 한다.

- VN 월별 스케줄표 1~7월 전체 데이터 적재
- 프로젝트별 전체 일정 생성
- 직원별 월간 일정표 생성
- 프로젝트 완료 시점 기준 납품일 자동 임시 지정
- 납품일 기준 보드 필터/그룹 수정
- 휴가/Off/Day/반차 관리
- 추가 업무, 야근, 일정 연장 결재 라우팅
- 작업자별 세부 작업내역 기록
- 일정 충돌 감지 및 중복 배정 허용/조정
- 알림 팝업
- 직원별 일정 조회 권한 매트릭스
- 사이드바 최소화 및 화면 공간 확보

## 0. 작업 전제

현재 프로젝트 폴더에는 실제 Excel 파일이 존재할 수 있다.

예상 파일명:

```text
(구조팀) VN 스케줄표_2026.07.01(1).xlsx
```

사용자가 제공한 화면 기준, 이 파일은 Workspace 프로젝트 루트에 위치한다.

예상 경로:

```text
F:\workspace\(구조팀) VN 스케줄표_2026.07.01(1).xlsx
```

Antigravity에서 열린 프로젝트 루트 기준:

```text
./(구조팀) VN 스케줄표_2026.07.01(1).xlsx
```

파일이 없으면 구현하지 말고 즉시 보고한다.

```text
[Excel 파일 미확인]
1. 현재 프로젝트 루트
2. 찾은 xlsx 파일 목록
3. 예상 파일명
4. 파일을 어디에 복사해야 하는지 안내
```

## 1. Plan 1~10과의 무결성 검토

### 1-1. Plan 1 연결

기본 흐름은 유지한다.

```text
수주 → PM 배정 → 일정 작성 → 승인/반려 → 카드형 업무 진행 → 완료
```

Excel 데이터는 이 흐름을 실제 프로젝트/업무/일정 seed로 채우는 역할을 한다.

```text
Excel Project List / Schedule Sheet
→ Project 생성
→ ScheduleAssignment 생성
→ TaskCard 생성
→ Project Summary Card 표시
→ 직원 일정표 표시
→ 전체 공정률 계산
```

### 1-2. Plan 2 연결

Plan 2의 일정 충돌, 선후행, 변경요청, 체크리스트, 산출물 기능은 유지한다. Plan 11에서는 동일 직원의 동일 날짜 다중 프로젝트 배정, 휴가/Off와 업무 일정 충돌, 야근/일정연장/추가업무 신청을 실제 ApprovalRequest와 연결한다.

### 1-3. Plan 3 연결

인사카드 기반 권한을 직원별 일정 조회 권한에 확장한다.

작업자는 기본적으로 다음 원칙을 따른다.

```text
작업자는 본인 일정과 본인 팀 일정만 본다.
작업자는 PM, 중간관리자, 최고관리자의 개인 일정은 볼 필요가 없다.
작업자는 타 팀 직원의 일정도 기본적으로 볼 수 없다.
```

### 1-4. Plan 4 연결

납품일 자동 지정, 납품일 변경, 휴가, 결재 라우팅, 충돌 해결은 모두 AuditLog, 필요 시 VersionSnapshot, Notification, ApprovalRequest와 연결한다.

### 1-5. Plan 5 연결

Plan 5의 1월 일부 샘플 검증을 확장해 2026년 1월~7월 전체 월별 섹션을 읽고 seed/dummy data로 저장한다.

### 1-6. Plan 6 연결

Project Board 첫 화면은 Project Summary Card 중심으로 유지한다. TaskCard는 상세라인 보드 또는 프로젝트 상세에서 보여준다. HealthScore는 계속 업무 리스크 지표이며 납품일 임박도, 평가점수와 혼동하지 않는다.

### 1-7. Plan 7 연결

Data Dictionary, Permission Scope, Selector, Test Matrix를 업데이트한다.

추가 selector 후보:

```ts
importMonthlyScheduleWorkbook(filePath)
parseScheduleMonthSection(sheet, month)
buildScheduleAssignmentsFromRows(rows)
groupAssignmentsToTaskCards(assignments)
deriveProjectDateRange(projectId)
deriveTemporaryDeliveryDate(projectId)
getProjectDeliveryBucket(projectId, today)
getMonthlyScheduleOptions()
canViewEmployeeSchedule(viewer, targetEmployee, schedule)
getVisibleEmployeeSchedules(viewer, employees, schedules)
getApprovalWorkflowForRequest(requestType, requester)
detectScheduleConflicts(assignments, taskCards)
suggestConflictResolution(conflict)
getTaskWorkSegments(taskId)
```

### 1-8. Plan 8 연결

TaskWorkSegment와 ScheduleAssignment는 향후 평가 참고자료로 사용할 수 있지만, 즉시 EvaluationScore에 자동 반영하지 않는다.

### 1-9. Plan 9 연결

QA Evidence Matrix와 최종 통합 리포트에 Plan 11 테스트 항목을 반영한다.

### 1-10. Plan 10 연결

Plan 10의 Project Summary Card 중심 보드, deliveryDate 기준 납품 임박도, 협업 보드/상세라인 보드 2개 구조, CONCOST/VIET_QS/QC 명칭, 상세라인 6단계, 직원 월간 그리드, 직원 프로젝트 통계 분리 원칙을 유지한다.

## 2. 1월~7월 VN 스케줄표 전체 더미데이터 적재

### 2-1. 대상 시트

1차 대상은 `2026★` 시트다. `Project List`는 프로젝트 메타데이터 매핑에 사용한다.

### 2-2. 대상 월

다음 월 섹션을 모두 감지한다.

```text
■ 1월 프로젝트 진행표
■ 2월 프로젝트 진행표
■ 3월 프로젝트 진행표
■ 4월 프로젝트 진행표
■ 5월 프로젝트 진행표
■ 6월 프로젝트 진행표
■ 7월 프로젝트 진행표
```

월 섹션은 하드코딩하지 말고 `프로젝트 진행표` 텍스트를 기준으로 탐색한다.

### 2-3. 생성 데이터

```text
Departments
PersonnelCards
Projects
ScheduleAssignments
TaskCards
PersonalSchedules
LeaveSchedules
ApprovalRequests seed
Notifications seed
AuditLogs seed
ProjectDeliveryDate seed
```

### 2-4. Project / Scope 조합

직원별 Project 행과 Scope 행을 묶어서 일자별 ScheduleAssignment를 생성한다.

예시:

```text
Project: The Hyundai
Scope: STEEL
Date: 2026-05-04
Employee: [DEMO] Viet QS Team Lead 039(퐁)
```

결과:

```ts
ScheduleAssignment {
  date: "2026-05-04"
  employeeId: "demo-vq-structure-024"
  projectName: "The Hyundai"
  scopeName: "STEEL"
  sourceMonth: 5
  sourceSheet: "2026★"
}
```

### 2-5. Off / Day / HALF Day 처리

다음 값은 일반 프로젝트 업무가 아니다.

```text
Off
Day
HALF Day
Morning
Afternoon
Vacation
Leave
Sick
Training
```

처리 방식:

- PersonalSchedule 또는 LeaveSchedule로 분리
- 업무 TaskCard로 만들지 않음
- 월간 일정표에서는 휴무/개인일정으로 표시
- 프로젝트 보드에서는 기본 숨김
- Off/Day 표시 토글이 켜진 경우만 표시

### 2-6. TaskCard 묶음 규칙

같은 직원 + 같은 프로젝트 + 같은 Scope + 연속 날짜는 하나의 TaskCard로 묶는다.

초기 권장:

```text
주말은 연속성 유지 가능
Off/Day/HALF Day는 연속성 끊음
프로젝트 또는 Scope가 바뀌면 끊음
```

### 2-7. Project 생성 규칙

- Project List에 있으면 Project List의 메타데이터를 우선 사용
- Project List에 없고 스케줄표에만 있으면 Excel Schedule 기반 임시 프로젝트 생성
- 프로젝트명 정규화 후 중복 제거
- 원본명은 sourceProjectName으로 보존
- 정규화명은 projectName/title로 사용

## 3. 프로젝트 완료 시점 기준 임시 납품일 자동 지정

### 3-1. 기본 규칙

```text
projectStartDate = 해당 프로젝트가 처음 등장한 날짜
projectEndDate = 해당 프로젝트가 마지막으로 등장한 날짜
temporaryDeliveryDate = projectEndDate + 7일
```

### 3-2. Project 필드

```ts
Project {
  startDate?: string
  dueDate?: string
  deliveryDate?: string
  deliveryDateSource?: "MANUAL" | "AUTO_FROM_SCHEDULE" | "PROJECT_LIST" | "UNKNOWN"
  deliveryDateStatus?: "UNSET" | "AUTO_ASSIGNED" | "MANUAL_CHANGED" | "OVERDUE" | "DELIVERED"
  deliveryDateUpdatedAt?: string
  deliveryDateUpdatedBy?: string
  deliveryDateChangeReason?: string
}
```

### 3-3. 자동 납품일 이력

```ts
DeliveryDateChange {
  id: string
  projectId: string
  beforeDeliveryDate?: string
  afterDeliveryDate: string
  changedBy: "system"
  reason: "프로젝트 최종 작업일 기준 7일 후 자동 임시 지정"
  source: "AUTO_FROM_SCHEDULE"
  createdAt: string
}
```

### 3-4. 수동 편집

납품일은 수동 편집 가능해야 한다.

권한:

- SUPER_ADMIN: 전체 가능
- DEPARTMENT_MANAGER: 본인 부서 가능
- PM: 본인 프로젝트 변경 요청 또는 권한 설정에 따라 직접 편집
- WORKER: 불가

수동 편집 시 변경 사유, AuditLog, DeliveryDateChange, Notification을 생성하고 납품 프리셋을 재계산한다.

## 4. 프로젝트 보드 필터 및 명칭 수정

### 4-1. 월별 보기 드롭다운

프로젝트 보드 상단에 월별 드롭다운을 추가한다.

```text
전체 기간
2026년 1월
2026년 2월
2026년 3월
2026년 4월
2026년 5월
2026년 6월
2026년 7월
```

동작:

- 선택 월에 해당하는 ScheduleAssignment / TaskCard / Project만 필터링
- Project Summary Card는 해당 월에 일정이 있는 프로젝트만 표시
- 전체 기간은 1~7월 전체 표시
- 직원 일정표도 동일한 월 선택 로직 공유

### 4-2. 프리셋 명칭 변경

현재 `긴급 / 높음 / 보통 / 낮음`은 다음으로 변경한다.

```text
납품 1주일 전
납품 2주일 전
납품 1달 전
미정
```

내부 bucket:

```ts
DeliveryPresetBucket {
  WITHIN_1_WEEK
  WITHIN_2_WEEKS
  WITHIN_1_MONTH
  UNSET
}
```

설명:

```text
납품 1주일 전: D-7 이내 또는 납품 초과
납품 2주일 전: D-8 ~ D-14
납품 1달 전: D-15 ~ D-30
미정: deliveryDate 없음
```

### 4-3. 명칭 변경

```text
작업자별 부하 → 진행중인 프로젝트
```

직원별 부하 통계는 별도 `직원 프로젝트 통계` 또는 `성과 평가` 영역에서 다룬다.

## 5. 휴가 / 개인 일정 / Off-Day 관리

### 5-1. LeaveSchedule 엔티티

```ts
LeaveSchedule {
  id: string
  userId: string
  departmentId: string
  leaveType: "OFF" | "DAY" | "HALF_DAY" | "VACATION" | "SICK" | "TRAINING" | "BUSINESS_TRIP" | "PERSONAL" | "ETC"
  title: string
  startDateTime: string
  endDateTime: string
  isAllDay: boolean
  source: "EXCEL" | "MANUAL" | "APPROVAL"
  approvalRequestId?: string
  status: "DRAFT" | "PENDING" | "APPROVED" | "REJECTED" | "CANCELLED" | "SCHEDULED"
  visibility: "SELF" | "TEAM" | "DEPARTMENT_MANAGER" | "PM_AND_ABOVE" | "SUPER_ADMIN_ONLY"
  createdBy: string
  createdAt: string
  updatedAt: string
}
```

### 5-2. 휴가 신청 흐름

휴가/반차/개인일정이 결재 대상이면 ApprovalRequest로 연결한다.

기본 라우팅:

```text
작업자 → PM → 중간관리자 → 최고관리자
```

단, 이 라우팅은 추후 편집 가능해야 한다.

### 5-3. 휴가와 일정 충돌

휴가가 승인되면 해당 기간의 업무 일정과 충돌 검사를 수행한다.

충돌 발생 시:

- PM 알림
- 중간관리자 알림
- 대체 인력 지정 또는 일정 변경 요청
- 충돌 해결 전까지 일정 경고 표시

## 6. 개별 직원 일정 조회 권한 매트릭스

### 6-1. ScheduleVisibilityRule 엔티티

```ts
ScheduleVisibilityRule {
  id: string
  viewerUserId: string
  targetUserId?: string
  targetTeamId?: string
  targetDepartmentId?: string
  canViewSchedule: boolean
  canViewPersonalSchedule: boolean
  canViewLeaveSchedule: boolean
  canViewProjectSchedule: boolean
  canViewPmSchedule: boolean
  canViewManagerSchedule: boolean
  reason?: string
  createdBy: string
  createdAt: string
  updatedAt: string
}
```

### 6-2. 기본 권한 정책

```text
SUPER_ADMIN:
- 모든 일정 조회 가능

DEPARTMENT_MANAGER:
- 본인 부서 전체 업무 일정 조회 가능
- 본인 부서 PM/작업자 업무 일정 조회 가능
- 개인 일정은 visibility 설정에 따름

PM:
- 본인 프로젝트에 속한 작업자 업무 일정 조회 가능
- 본인 팀 또는 본인 프로젝트 일정 조회 가능
- 다른 PM/관리자 개인 일정은 기본 미노출

WORKER:
- 본인 일정 조회 가능
- 본인 팀 업무 일정 조회 가능
- 타 팀 일정 기본 미노출
- PM 이상 개인 일정 기본 미노출
```

### 6-3. 직원별 예외 설정

관리자는 직원별로 예외를 설정할 수 있어야 한다.

예시:

```text
Phong → Slab Team 일정만 조회 가능
Phong → PM 일정 미노출
Phong → Wall Team 일정 미노출
Phong → 본인 프로젝트 관련자 일정만 조회 가능
```

필수 selector:

```ts
canViewEmployeeSchedule(viewer, targetEmployee, schedule)
getVisibleEmployeesForSchedule(viewer)
getVisibleSchedulesForEmployee(viewer, targetEmployee)
```

## 7. 추가 업무 / 야근 / 일정 연장 결재 라우팅

### 7-1. 기본 결재 라우팅

```text
작업자 → PM → 중간관리자 → 최고관리자
```

요청 유형별 예시:

```text
야근 신청: 작업자 → PM → 중간관리자
일정 연장: 작업자 → PM → 중간관리자
추가 업무: 작업자 → PM → 중간관리자
대형 일정 변경: PM → 중간관리자 → 최고관리자
휴가 신청: 작업자 → PM 또는 중간관리자
```

### 7-2. ApprovalWorkflowTemplate

```ts
ApprovalWorkflowTemplate {
  id: string
  requestType: string
  title: string
  steps: ApprovalWorkflowStep[]
  editableByRoles: string[]
  isDefault: boolean
  createdAt: string
  updatedAt: string
}
```

```ts
ApprovalWorkflowStep {
  id: string
  order: number
  approverRole: "PM" | "DEPARTMENT_MANAGER" | "SUPER_ADMIN" | "QC_REVIEWER" | "CUSTOM_USER"
  approverUserId?: string
  isRequired: boolean
  canDelegate: boolean
}
```

### 7-3. ApprovalRequest 확장

```ts
ApprovalRequest {
  workflowTemplateId?: string
  currentStepOrder?: number
  approvalPath?: ApprovalWorkflowStep[]
  finalDecision?: "APPROVED" | "REJECTED" | "ALTERNATIVE_APPROVED"
  alternativeAction?: "EXTEND_SCHEDULE" | "APPROVE_OVERTIME" | "REASSIGN_WORK" | "ALLOW_OVERLAP" | "POSTPONE_OTHER_TASK"
}
```

### 7-4. 중간관리자 대안 승인

야근 신청이 들어왔지만 일정이 널널한 경우, 중간관리자는 다음 대안을 선택할 수 있어야 한다.


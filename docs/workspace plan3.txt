# WORKSPACE PLAN 3 — 권한별 화면 분리, 인사카드 기반 권한, 관리자/PM 개인 일정 보강 프롬프트

이 프롬프트는 기존 MASTER PROMPT 및 ADDITIONAL PROMPT에 추가되는 보강 지시사항이다.

기존 개발 목표인 “Notion 스타일 카드형 통합업무관리 시스템”은 유지하되, 아래 기능을 반드시 추가 설계에 반영하라.

이번 추가 요구사항의 핵심은 다음과 같다.

1. 권한별로 보이는 화면과 데이터 범위가 달라야 한다.
2. 최고관리자는 모든 부서, 모든 PM, 모든 작업자 일정을 볼 수 있어야 한다.
3. 중간관리자는 본인 부서의 전체 일정과 소속 PM/작업자 일정을 볼 수 있어야 한다.
4. PM은 본인이 배정받은 프로젝트와 해당 프로젝트의 진행도, 담당 작업자 일정을 볼 수 있어야 한다.
5. 작업자는 본인에게 배정된 일정과 업무만 볼 수 있어야 한다.
6. 인사카드를 제공하면 해당 인사카드 정보를 바탕으로 권한 세팅이 가능해야 한다.
7. 작업자뿐 아니라 PM과 중간관리자도 개인 일정이 존재해야 한다.
8. 중간관리자 일정은 중간관리자가 직접 추가 및 변경 가능해야 한다.
9. PM 일정은 PM이 직접 추가 및 변경 가능하지만, 변경 사실은 중간관리자에게 통보되어야 한다.
10. PM 일정 변경은 추후 승인 프로세스로 확장 가능하게 설계해야 한다.

절대 한 번에 전부 구현하지 말고, 기존 Phase 흐름을 유지하면서 필요한 Phase에 선반영하거나, Phase 15 이후 확장 Phase로 분리하라.

## 1. 권한 체계 재정의

기존 역할에 다음 역할을 명확하게 추가하거나 재정의한다.

### 1-1. 최고관리자 / Super Admin

최고관리자는 시스템 전체를 총괄한다.

권한:

- 모든 부서 일정 조회
- 모든 프로젝트 조회
- 모든 PM 일정 조회
- 모든 작업자 일정 조회
- 모든 중간관리자 일정 조회
- 전체 승인 요청 조회
- 전체 야근/추가일정 신청 조회
- 전체 업무 순서 변경 이력 조회
- 전체 AuditLog 조회
- 사용자/부서/권한 관리
- 인사카드 기반 권한 세팅
- 부서별 업무량 비교
- PM별 업무량 비교
- 작업자별 업무량 비교

### 1-2. 중간관리자 / Department Manager

중간관리자는 본인 부서를 관리한다.

권한:

- 본인 부서 전체 프로젝트 조회
- 본인 부서 전체 일정 조회
- 본인 부서 PM 일정 조회
- 본인 부서 작업자 일정 조회
- 본인 부서 프로젝트 승인/반려
- 본인 부서 업무 추가 승인/반려
- 본인 부서 야근/추가일정 신청 확인
- 본인 부서 PM 일정 변경 알림 수신
- 본인 개인 일정 직접 추가
- 본인 개인 일정 직접 변경
- 본인 개인 일정 삭제
- 본인 부서 업무량 확인
- 본인 부서 일정 충돌 확인

제한:

- 다른 부서 일정은 기본적으로 볼 수 없다.
- 다른 부서 인력의 개인 일정은 볼 수 없다.
- 최고관리자 권한 기능은 사용할 수 없다.

### 1-3. PM / Project Manager

PM은 본인이 배정받은 프로젝트를 관리한다.

권한:

- 본인이 배정받은 프로젝트 조회
- 본인이 배정받은 프로젝트 진행도 조회
- 본인 프로젝트에 속한 업무 카드 조회
- 본인 프로젝트에 속한 작업자 일정 조회
- 본인 프로젝트 업무 일정 작성
- 본인 프로젝트 업무 카드 생성
- 본인 프로젝트 업무 순서 조정
- 본인 프로젝트 작업자 배정
- 본인 개인 일정 직접 추가
- 본인 개인 일정 직접 변경
- 본인 개인 일정 삭제
- PM 일정 변경 시 중간관리자에게 알림 자동 생성
- 추후 PM 일정 변경 승인 프로세스 확장 가능

제한:

- 본인이 배정받지 않은 프로젝트는 볼 수 없다.
- 다른 PM의 프로젝트는 볼 수 없다.
- 중간관리자 승인 권한은 없다.
- 최고관리자 기능은 사용할 수 없다.

### 1-4. 작업자 / Worker

작업자는 본인에게 배정된 업무를 수행한다.

권한:

- 본인에게 배정된 업무 조회
- 본인 업무 일정 조회
- 본인 업무 진행률 수정
- 본인 업무 완료 처리 또는 완료 요청
- 업무 추가 신청
- 야근 신청
- 일정 연장 신청
- 본인 업무 관련 댓글 작성
- 본인 업무 관련 산출물 등록

제한:

- 타인의 업무는 기본적으로 볼 수 없다.
- 전체 프로젝트 일정은 볼 수 없다.
- PM 일정은 볼 수 없다.
- 중간관리자 일정은 볼 수 없다.
- 승인 권한은 없다.

인사카드 정보를 기반으로 사용자의 권한, 부서, 직책, 프로젝트 접근 범위를 자동 또는 수동으로 설정할 수 있어야 한다.

### 3-1. PersonnelCard 엔티티 추가

다음 데이터 구조를 추가한다.

PersonnelCard:

- id
- employeeNumber
- name
- email
- phone
- departmentId
- departmentName
- position
- jobTitle
- role
- permissionLevel
- managerId
- pmId
- employmentStatus
- joinedAt
- profileImageUrl

- defaultWorkEndTime

- canManageProjects

### 3-2. 인사카드 입력 방식

초기 구현에서는 다음 방식 중 하나 이상을 지원한다.

- 수동 입력
- CSV 업로드 준비 구조
- Mock 인사카드 데이터
- 추후 엑셀 업로드 확장 가능 구조

### 3-3. 인사카드 기반 권한 자동 매핑

인사카드의 role, departmentId, managerId, pmId, permissionLevel을 기준으로 시스템 접근 범위를 설정한다.

예시:

- role이 SUPER_ADMIN이면 전체 부서 접근 허용
- role이 DEPARTMENT_MANAGER이면 departmentId 기준 본인 부서 접근 허용
- role이 PM이면 본인이 pmId로 지정된 프로젝트 접근 허용
- role이 WORKER이면 assigneeId가 본인인 업무만 접근 허용

### 3-4. 인사카드 관리 화면

최고관리자 또는 관리자 전용 화면으로 제공한다.

필수 기능:

- 인사카드 목록

- 역할별 필터
- 권한 레벨 표시
- 직원 상세 보기
- 역할 변경
- 부서 변경
- 상위 관리자 지정
- PM 연결
- 근무 가능 시간 설정
- 활성/비활성 처리

## 5. 중간관리자 개인 일정 규칙

중간관리자는 본인 개인 일정을 직접 추가, 변경, 삭제할 수 있어야 한다.

### 기능

- 중간관리자 내 개인 일정 화면
- 일정 추가
- 일정 변경
- 일정 삭제
- 일정 완료 처리
- 부서 공정표와 함께 표시
- 최고관리자는 해당 일정을 조회 가능

### 규칙

- 중간관리자의 개인 일정은 기본적으로 본인과 최고관리자에게 노출된다.
- visibility가 DEPARTMENT이면 부서 구성원에게도 일부 노출 가능하다.
- 중간관리자가 본인 일정을 변경해도 별도 승인 절차는 필요하지 않다.
- 단, 변경 이력은 AuditLog에 남긴다.

## 6. PM 개인 일정 규칙

PM은 본인 개인 일정을 직접 추가, 변경, 삭제할 수 있어야 한다.

단, PM 일정 변경은 중간관리자에게 자동 통보되어야 한다.

### 기능

- PM 내 개인 일정 화면
- 일정 추가
- 일정 변경
- 일정 삭제
- 일정 완료 처리
- PM 프로젝트 일정과 함께 표시
- 중간관리자에게 PM 일정 변경 알림 생성
- 최고관리자는 전체 PM 일정 조회 가능

### 규칙

- PM은 본인 일정을 직접 추가할 수 있다.
- PM은 본인 일정을 직접 변경할 수 있다.
- PM이 일정을 추가, 변경, 삭제하면 본인 소속 중간관리자에게 Notification 생성
- Notification type은 PM_SCHEDULE_CHANGED로 한다.
- PM 일정 변경은 현재 단계에서는 승인 없이 반영한다.
- 단, 추후 승인 프로세스로 바꿀 수 있도록 requiresApproval 필드를 준비한다.
- requiresApproval이 true인 경우 ApprovalRequest로 연결 가능하게 설계한다.

### PM 일정 변경 알림 예시

알림 제목:

PM 일정이 변경되었습니다.

알림 내용:

[PM 이름]이 [일정명] 일정을 변경했습니다. 변경된 시간: [기존 시간] → [변경 시간]

## 7. 일정 통합 표시 규칙

직원별 공정표에는 업무 카드 일정과 개인 일정이 함께 표시되어야 한다.

### 표시 대상

- TaskCard 기반 업무 일정
- Project 기반 프로젝트 일정
- PersonalSchedule 기반 개인 일정
- ApprovalRequest 기반 승인 대기 일정
- Overtime / Deadline Extension 신청 일정

### 권한별 통합 일정 표시 범위

최고관리자:

- 모든 부서의 프로젝트 일정
- 모든 PM 일정
- 모든 작업자 업무 일정
- 모든 중간관리자 개인 일정
- 모든 승인 대기 일정

중간관리자:

- 본인 부서 프로젝트 일정
- 본인 부서 PM 개인 일정
- 본인 부서 작업자 업무 일정
- 본인 개인 일정
- 본인 부서 승인 대기 일정

PM:

- 본인 프로젝트 일정
- 본인 프로젝트 작업자 일정
- 본인 개인 일정
- 본인 프로젝트 승인 대기 일정

작업자:

- 본인 업무 일정
- 본인 개인 업무 일정이 있을 경우 본인 것만
- 본인 승인 신청 상태

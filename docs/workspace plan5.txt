# WORKSPACE PLAN 5 — VN 월별 스케줄표 데이터화 및 샘플 데이터 검증 프롬프트

이 프롬프트는 기존 `workspace plan1.txt`, `workspace plan2.txt`, `workspace plan3.txt`, `workspace plan4.txt` 이후에 추가되는 다섯 번째 보강 지시사항이다.

이번 Plan 5의 목적은 실제로 사용 중인 월별 업무 스케줄표 Excel을 기준으로, 통합업무관리 시스템이 원하는 방식으로 구동되는지 검증하기 위한 **샘플 데이터 세트**를 구축하는 것이다.

기존 Plan 1~4는 시스템의 구조, 권한, 승인, 일정, 예외처리, 운영 안정성을 정의한다.  
Plan 5는 그 시스템이 실제 업무 스케줄 데이터와 맞는지 확인하기 위한 **현실 기반 Mock Data / Seed Data / Fixture Data 구축 지시서**다.

---

## 0. 작업 대상 파일

현재 작업 폴더 또는 프로젝트 폴더에는 아래 Excel 파일이 제공될 수 있다.

```text
(구조팀) VN 스케줄표_2026.07.01(1).xlsx
```

이 파일은 베트남 구조팀의 월별 업무 스케줄표이며, 기존 통합업무관리 시스템의 데이터 모델이 실제 업무 스케줄을 표현할 수 있는지 검증하는 기준 파일이다.

Antigravity는 이 파일을 발견하면 먼저 구조를 분석해야 한다.

파일이 현재 프로젝트 폴더 안에 없다면 바로 구현하지 말고 사용자에게 다음 중 하나를 요청하라.

1. Excel 파일을 현재 프로젝트 루트에 복사
2. Excel 파일을 `data/import/` 폴더에 복사
3. Excel 파일 없이 Plan 5에 정의된 샘플 구조만으로 fixture 데이터를 먼저 생성

---

## 1. 매우 중요한 원칙

- 이 Plan 5는 실제 운영 DB 마이그레이션이 아니다.
- 초기 목표는 Excel 전체 자동 import가 아니라, 실제 스케줄표 구조를 반영한 샘플 데이터 구축이다.
- 먼저 Excel 구조를 분석하고, 샘플 데이터를 만든 뒤, 화면이 원하는 방식으로 작동하는지 검증한다.
- Excel 파일 전체를 무리하게 한 번에 파싱하지 마라.
- 처음에는 2026년 1월~2월 또는 2026년 1월 일부 데이터만 샘플로 변환해도 된다.
- 이후 사용자가 승인하면 2026년 1월~7월 전체로 확장한다.
- 샘플 데이터는 기존 Plan 1~4의 데이터 모델과 충돌하지 않게 만들어야 한다.
- 샘플 데이터는 화면 테스트, 권한 테스트, 일정표 테스트, 업무 카드 테스트에 바로 사용할 수 있어야 한다.
- 파일을 읽기 전에는 구현하지 마라.
- 파일을 읽은 뒤에는 반드시 구조 분석 보고서를 먼저 작성하라.
- 사용자가 승인하기 전까지 실제 코드 수정, 파일 생성, 커밋을 진행하지 마라.

## 2. Excel 파일 구조 분석 기준

Excel 파일에는 다음과 같은 시트가 있을 수 있다.

```text
Project List
2026★
2025
2024
```

### 2-1. Project List 시트

`Project List` 시트는 프로젝트 메타데이터를 담고 있다.

주요 컬럼 예시:

- Year
- No
- Project No
- Color
- 프로젝트명 Kr
- 프로젝트명 Eng
- 현황 Progress
- PM
- 거래처
- 건물용도
- 비고

Antigravity는 이 시트를 기준으로 프로젝트 목록을 추출하거나, 최소한 프로젝트명 매핑에 참고해야 한다.

초기 샘플에서는 모든 프로젝트를 완벽히 매핑하지 않아도 된다.  
단, 스케줄표에 등장하는 프로젝트명이 `Project List`에 있는 경우 연결 가능하도록 구조를 설계하라.

### 2-2. 연도별 스케줄 시트

`2026★`, `2025`, `2024` 시트는 월별 스케줄표를 담고 있다.

예상 구조:

- 월별 섹션 제목: `■ 1월 프로젝트 진행표`, `■ 2월 프로젝트 진행표` 등
- 월별 섹션은 세로로 반복 배치된다.
- 각 월 섹션의 날짜는 가로 방향으로 배치된다.
- 직원은 세로 방향으로 배치된다.
- 한 직원은 보통 2개 행을 가진다.
  - 첫 번째 행: `Project`
  - 두 번째 행: `Scope`
- 날짜별 업무는 같은 날짜 컬럼에서 Project 값과 Scope 값을 조합해서 하나의 일정으로 만든다.

### 2-3. 2026년 시트에서 확인되는 월 섹션 예시

2026년 시트에는 다음 월 섹션이 존재할 수 있다.

```text
■ 1월 프로젝트 진행표
■ 2월 프로젝트 진행표
■ 3월 프로젝트 진행표
■ 4월 프로젝트 진행표
■ 5월 프로젝트 진행표
■ 6월 프로젝트 진행표
■ 7월 프로젝트 진행표
```

이 구조는 파일마다 달라질 수 있으므로, 하드코딩하지 말고 `프로젝트 진행표` 텍스트를 찾아 월별 섹션을 감지하라.

## 3. Excel → 데이터 변환 규칙

### 3-1. 날짜 변환

Excel 날짜 숫자는 ISO 날짜로 변환한다.

예시:

```text
46023 → 2026-01-01
46113 → 2026-04-01
```

변환 결과는 반드시 `YYYY-MM-DD` 형식으로 저장한다.

### 3-2. 직원 정보 변환

직원 행에서 다음 정보를 추출한다.

- 팀 구분
- 세부 그룹
- 직급
- 성명
- 한글 별칭이 있으면 보존
- 베트남어 이름 원문 보존

예시:

```text
Team: Slab Team
Group: A . S
Rank: 팀장
Name: [DEMO] Viet QS Team Lead 039(퐁)
```

직원 데이터는 기존 Plan 3의 `PersonnelCard` 구조와 연결되도록 만든다.

### 3-3. Project / Scope 행 조합

한 직원은 보통 2개 행으로 구성된다.

예시:

```text
Project 행: Sangincheon
Scope 행: RC(HOR)
```

이 경우 하나의 일정 데이터는 다음처럼 생성한다.

```json
{
  "date": "2026-01-02",
  "employeeName": "[DEMO] Viet QS Team Lead 039(퐁)",
  "projectName": "Sangincheon",
  "scopeName": "RC(HOR)"
}
```

### 3-4. 빈 값 처리

다음 값은 일정 데이터로 만들지 않는다.

- 빈 셀
- 날짜가 없는 셀
- 직원명이 없는 행
- Project와 Scope가 모두 비어 있는 셀

### 3-5. 휴무 / 반차 / 개인일정 처리

다음 값은 일반 프로젝트 업무가 아니라 개인 일정 또는 근태성 일정으로 분류한다.

- Off
- Day
- HALF Day
- Morning
- Afternoon
- Vacation
- Leave
- Sick
- Training

분류 예시:

```json
{
  "type": "PERSONAL_SCHEDULE",
  "scheduleType": "OFF",
  "date": "2026-01-05",
  "employeeName": "[DEMO] Viet QS Deputy Lead 040(늣끄엉)"
}
```

단, 초기 샘플에서는 `Off`, `Day`, `HALF Day`만 우선 처리해도 된다.

### 3-6. 프로젝트명 정규화

Excel에는 줄바꿈, 공백, 축약어가 섞여 있을 수 있다.

예시:

```text
Sangin
cheon → Sangincheon
Guri 
Sutaek → Guri Sutaek
Hanwha 
 Shipyard → Hanwha Shipyard
 Hi-Tech  → Hi-Tech
```

정규화 규칙:

- 줄바꿈은 공백으로 바꾼다.
- 앞뒤 공백은 제거한다.
- 연속 공백은 하나로 줄인다.
- 원본 값도 `sourceProjectName`으로 보존한다.
- 정규화한 값은 `projectName`으로 저장한다.

### 3-7. Scope 정규화

Scope 값도 줄바꿈과 공백을 정리한다.

예시:

```text
RC
(HOR) → RC(HOR)
Steel All
(H+V) → Steel All(H+V)
DWG Changes → DWG Changes
```

원본 값은 `sourceScopeName`으로 보존하고, 정규화 값은 `scopeName`으로 저장한다.

## 4. 생성해야 할 샘플 데이터 구조

Antigravity는 Excel을 분석한 뒤, 기존 프로젝트 구조에 맞춰 아래 중 하나의 방식으로 샘플 데이터를 생성하라.

기존 프로젝트가 TypeScript 기반이면 다음을 우선한다.

```text
src/data/workspaceScheduleSeed.ts
```

또는 프로젝트 구조에 따라 다음 위치를 사용할 수 있다.

```text
src/mocks/workspaceScheduleSeed.ts
src/lib/mock/workspaceScheduleSeed.ts
data/seed/workspaceScheduleSeed.json
```

파일 위치는 Phase 0 분석 후 사용자에게 제안하라.

### 4-1. 생성할 데이터 세트

4. `sampleTaskCards`
5. `sampleScheduleAssignments`
6. `samplePersonalSchedules`

## 5. TaskCard 생성 규칙

Excel의 일자별 셀 하나하나를 모두 TaskCard로 만들면 카드가 너무 많아질 수 있다.

따라서 TaskCard는 다음 방식 중 하나로 묶어서 생성하라.

### 5-1. 권장 방식

같은 직원 + 같은 프로젝트 + 같은 Scope + 연속된 날짜는 하나의 TaskCard로 묶는다.

예시:

```text
[DEMO] Viet QS Team Lead 039(퐁)
2026-01-05 ~ 2026-01-08
Sangincheon
RC(HOR)
```

위 데이터는 일별 assignment 4개로 저장하되, 카드 화면에서는 하나의 TaskCard로 표시한다.

### 5-2. TaskCard 예시

```ts
export const sampleTaskCards = [
```

## 7. 샘플 데이터 검증 규칙

샘플 데이터 생성 후 반드시 다음 검증을 수행하라.

### 7-1. 데이터 무결성

- 모든 `scheduleAssignment`에는 `date`, `employeeId`, `projectName`, `scopeName`이 있어야 한다.
- 모든 `employeeId`는 `samplePersonnelCards`에 존재해야 한다.
- 모든 `projectId`는 `sampleProjects`에 존재해야 한다.
- `Off`, `Day`, `HALF Day`는 일반 `TaskCard`로 생성되지 않아야 한다.
- 빈 셀은 데이터로 생성되지 않아야 한다.
- sourceSheet, sourceMonth, sourceRow, sourceColumn 등 추적 정보가 있어야 한다.

### 7-2. 일정 무결성

- 같은 직원의 같은 날짜에 여러 업무가 있을 경우 충돌 표시가 가능해야 한다.
- 연속 날짜는 TaskCard로 묶을 수 있어야 한다.
- 주말/휴무는 구분되어야 한다.
- Excel 날짜와 변환된 ISO 날짜가 일치해야 한다.

### 7-3. 권한 무결성

- 최고관리자는 모든 샘플 일정을 볼 수 있어야 한다.
- 중간관리자는 본인 부서 일정만 볼 수 있어야 한다.
- PM은 본인 프로젝트 일정만 볼 수 있어야 한다.
- 작업자는 본인 일정만 볼 수 있어야 한다.

### 7-4. UI 무결성

- 카드형 보드에서 TaskCard가 표시되어야 한다.
- 월별 공정표에서 assignment가 표시되어야 한다.
- Off / Day는 업무 카드가 아니라 개인 일정 또는 근태성 일정으로 표시되어야 한다.
- Project와 Scope가 함께 보이도록 표시되어야 한다.
- 줄바꿈이 있는 프로젝트명은 정리되어 보여야 한다.

## 기존 프롬프트와의 연결 지시

이 프롬프트는 기존 `workspace plan1.txt`, `workspace plan2.txt`, `workspace plan3.txt`, `workspace plan4.txt` 이후에 추가되는 다섯 번째 보강 프롬프트다.

Antigravity는 다음 순서를 반드시 지켜야 한다.

1. `workspace plan1.txt`를 먼저 읽는다.
2. `workspace plan2.txt`를 읽는다.
3. `workspace plan3.txt`를 읽는다.
4. `workspace plan4.txt`를 읽는다.
5. `workspace plan5.txt`를 읽는다.
6. Excel 파일이 있으면 구조를 분석한다.
7. Excel 파일이 없으면 사용자에게 파일 위치를 확인한다.
8. Phase 0 보고서에 Plan 5의 샘플 데이터화 요구사항을 함께 반영한다.
9. 기존 Phase 0~25의 흐름을 무너뜨리지 않는다.
10. Plan 5의 실제 구현은 Phase 26 이후 확장 단계로 진행한다.
11. 사용자 승인 없이 다음 Phase로 넘어가지 않는다.

현재는 아직 구현을 시작하지 마라.

먼저 `workspace plan1.txt`, `workspace plan2.txt`, `workspace plan3.txt`, `workspace plan4.txt`, `workspace plan5.txt` 전체를 읽고 Phase 0 분석부터 시작하라.
